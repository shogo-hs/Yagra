## 0. TL;DR
- M-03 実装完了後に残っている進捗ドキュメントの状態不整合を解消する。
- `goals / milestones / progress` の状態・現在地文言を現実の実装状況にそろえる。
- 変更はドキュメントのみで、コード挙動や公開 API への影響はない。

## 1. 背景 / 課題
- 現在、`docs/product/milestones.md` の M-01 が `In Progress` のままで、M-01 の完了条件と実装状態にズレがある。
- `docs/product/goals.md` の G-02 も `In Progress` だが、`docs/product/progress.md` では G-02 のやるべきことが全て `Done` となっている。
- `docs/product/progress.md` の G-02 現在地文言に「次は M-03 へ進む段階」が残っており、M-03 完了後の現状と一致しない。

## 2. ゴール / 非ゴール
### 2.1 ゴール
- 進捗管理ドキュメント3点の状態と記述を、最新の実装・完了状況に一致させる。
- 状態値（Done/In Progress）と現在地テキストの矛盾を解消する。

### 2.2 非ゴール
- 新機能実装やテスト追加は行わない。
- Goal/Milestone 定義そのもの（文言仕様や運用ルール）の再設計は行わない。

## 3. スコープ / 影響範囲
- 変更対象: `docs/product/goals.md`, `docs/product/milestones.md`, `docs/product/progress.md`
- 影響範囲: プロダクト計画の参照者（開発者/レビュー担当）の認識一致。
- 互換性: ドキュメントのみ変更のため後方互換問題なし。
- 依存関係: 既存の M-01/M-02/M-03 実装完了状態に依存。

## 4. 要件
### 4.1 機能要件
- `docs/product/milestones.md` の M-01 状態を完了条件に照らして更新する。
- `docs/product/goals.md` の G-02 状態を実施状況に合わせて更新する。
- `docs/product/progress.md` の G-02 現在地文言を、M-03 完了後の状態に更新する。
- 3ファイル間で状態矛盾がないことを確認する。

### 4.2 非機能要件 / 制約
- Markdown 構造（見出し/表形式）を維持する。
- 更新日は `最終更新: 2026-02-13` のままとし、同日内整合更新として扱う。
- 既存ID（G-xx, M-xx, Item ID）は追加・削除しない。

## 5. 仕様 / 設計
### 5.1 全体方針
- 「完了条件を満たしているか」を基準に状態を更新する。

- テキスト修正は必要最小限に留め、履歴可読性を維持する。
